# Progress, memory, and handoffs

File context survives only when it is actually saved and available to the next session.

## What to update

| Information | Destination |
| --- | --- |
| Confirmed preferences / constraints | context/STUDENT_PROFILE.md |
| Course paths, confirmed deadlines, focus | context/DASHBOARD.md |
| Decisions / corrections used across courses | context/MEMORY.md |
| Objective performance and reasoning errors | Course Progress.md |
| Exam-specific readiness | Exam Progress.md |
| Current task, artifact paths, next step | Task Handoff.md |
| Latest task pointer | context/HANDOFF.md |

Use local dates and a timezone for deadlines. Keep source/evidence references attached to factual claims. Do not record sensitive personal details unless necessary and explicitly supplied for this purpose.

## Evidence of learning

Use: not assessed; developing; demonstrated; needs revisit. Record date, objective, independent response/method, error pattern, assistance given, and next review. Do not invent scores or automatically label a topic mastered.

One assisted/correct answer supports developing. Demonstrated requires correct explanation/application on at least two distinct attempts, including a later independent check; this is a system review heuristic, not a validated grade prediction. Student confidence is separate from performance. Misses or outdated material can change the status.

Propose spaced review based on remaining time and performance, using the student's schedule. Do not claim exact intervals guarantee retention.

## Save while working

After a meaningful preference change, correction, practice result, or completed artifact, update the relevant small file. Save a checkpoint during long tasks and before context becomes crowded. Never wait for the student to remember a special command.

At task end, record what finished, what remains, the next action, pending input, source locations, and exact output paths. Keep any unanswered question without revealing its answer. Course/task handoffs hold detail; the root only points to them.

## Keep context small

Profile and dashboard target under 500 words each; global memory under 400; handoff under 250. These are maintenance targets, not measured token guarantees. Course Progress keeps current evidence summaries; detailed older practice can be linked in archive. Compact repetitive entries while preserving decisions and unresolved errors. Never discard unique student work automatically.

With no write access, provide a paste-ready update per exact filename and say it is not yet saved. For manual projects, the student replaces the old uploaded versions. Never claim Git/cloud sync happened without checking.

For concurrent chats, read the latest file before writing, merge different updates, and avoid overwriting another task's handoff. If tools cannot safely merge, provide the proposed update for review.
